Base: `d84bde60ff5087928606ad543c385aae0541f94d`. Physical host: Shopify POS 11.16.2 (530647), Demo store / Brooklyn. This follow-up is not a customer deployment or complete parity sign-off.

Temporary on-device tracing established that session authentication and OMS lease acquisition completed, then `CountState.open` stalled during local document recovery. `CountStorage.sweep` continued beyond 4,400 overflow indices, with both native `delete` results reported as boolean `true`. The store permits only 100 entries; these results cannot represent thousands of existing overflow values. The old loop used those acknowledgements as existence checks and never reached its stop condition. This differs from the documented Storage API absent-key return contract.

Recovery now reads overflow key presence and stops at the first absent pair. It ignores deletion acknowledgements for termination. The committed root, referenced slots, schema, high-water mark, migration and ascending-write crash recovery protocol stay intact. No KV data was cleared to diagnose or fix the issue. Temporary tracing was removed.
